# Смакова ліга · GitHub Cloud

Версія застосунку з офлайн-роботою, резервними копіями JSON та GitHub-синхронізацією **за схемою MEDIA / LOG**.

## Що є в архіві

| Файл | Призначення |
| --- | --- |
| `index.html` | Повний застосунок з двобоями, Elo, SVG-іконками, стравами й налаштуваннями |
| `data.json` | Початкова хмарна база з **42 стравами**. УВАГА: не перезавантажуйте цей файл на GitHub після першої синхронізації, інакше зітрете хмарний прогрес! |
| `cloud-config.js` | **Публічні** URL Worker і Google Client ID; токенів тут немає |
| `.nojekyll` | Спрощує роботу GitHub Pages |
| `worker/src/index.js` | Cloudflare Worker: перевіряє Google ID token на сервері, читає й комітить `data.json` |
| `worker/wrangler.toml` | Параметри Worker для майбутнього репозиторію `zbys1av/smakova-liha` |
| `worker/tests/smoke.mjs` | Автономні тести Worker: читання, авторизація, помилковий доступ, конфлікт SHA |

## Як це працює

1. Відвідувач заходить на GitHub Pages; застосунок автоматично перевіряє `data.json` (напряму або через Worker).
2. Дані й результати кожного двобою як і раніше одразу пишуться в `localStorage`. Можна працювати **офлайн**.
3. Якщо локальних даних на цій адресі сайту немає, початкова база автоматично завантажується з GitHub. Якщо локальні зміни є, **вони не перезаписуються**.
4. У **Налаштування → GitHub Cloud** можна «Перевірити GitHub», «Завантажити з GitHub», «Використати локальну версію», «Зберегти в GitHub».
5. Збереження потребує Google-входу під дозволеним власником; Worker перевіряє **цифровий підпис Google**, аудиторію, термін дії та власника ID-токена.
6. GitHub PAT міститься виключно в Cloudflare Worker Secret. Він **не потрібен** і **не вводиться** в браузері.
7. Перед кожним записом перевіряється GitHub SHA. Конфлікт між двома пристроями не призводить до непомітної втрати даних: збереження блокується, користувач вручну обирає версію. Автоматичного злиття різних історій немає.
8. Кнопка Google входу доступна **лише на HTTPS-сторінці з налаштованим Worker**. Відкритий напряму локальний `.html` працює офлайн, без хмарного запису.

## Крок 1. GitHub Pages

1. Зробіть **JSON-резервну копію** зі старої «Смакової ліги» через «Налаштування → Завантажити JSON».
2. Створіть окремий GitHub-репозиторій, рекомендована назва **`smakova-liha`**, власник **`zbys1av`**. Не використовуйте репозиторій `media-log` для цієї програми.
3. Завантажте у корінь гілки `main` файли `index.html`, `data.json`, `cloud-config.js`, `.nojekyll` (а також `README_UA.md`, папку `worker/` за бажанням).
4. У GitHub: **Settings → Pages → Build and deployment → Deploy from a branch → main → /(root) → Save**.
5. Сторінка стане доступною за адресою `https://zbys1av.github.io/smakova-liha/` після публікації Pages.
6. До налаштування Worker сайт може **читати** `data.json`, а локальний режим та JSON-імпорт/експорт продовжують працювати.

## Крок 3. GitHub fine-grained PAT

1. Відкрийте https://github.com/settings/personal-access-tokens/new.
2. **Repository access → Only select repositories → `zbys1av/smakova-liha`**.
3. **Repository permissions → Contents → Read and write**. Більше прав не потрібно.
4. Скопіюйте PAT у менеджер паролів. **Не надсилайте токен у чат, не додавайте до index.html, cloud-config.js або wrangler.toml!**
5. Токен для `media-log` з обмеженням лише на `media-log` не має прав до нового репозиторію — створіть окремий токен.

## Крок 4. Cloudflare Worker

1. Встановіть Node.js (якщо відсутній) і розпакуйте архів.
2. У терміналі перейдіть до каталогу `worker/` і виконайте:

```bash
npx wrangler login
npx wrangler deploy
npx wrangler secret put GITHUB_TOKEN
```

3. Остання команда запитає PAT у секретному полі. Підтвердьте.
4. URL Worker буде схожим на `https://smakova-liha-sync.XXXX.workers.dev`. Відкрийте `URL/health`: має показати `{"ok":true,"service":"smakova-liha-github"}`.
5. У кореневому файлі `cloud-config.js` змініть лише поле `apiUrl` на **реальну адресу цього Worker** (без `/data` наприкінці). Збережіть файл у GitHub.

Приклад:

```js
window.SMAKOVA_CLOUD = {
  apiUrl: "https://smakova-liha-sync.YOUR-SUBDOMAIN.workers.dev",
  googleClientId: "337139173285-uh3rdtn6ou7mjodi5stgc966f89cbtak.apps.googleusercontent.com",
  publicDataUrl: "./data.json"
};
```

Параметри `GITHUB_OWNER`, `GITHUB_REPO`, `GITHUB_BRANCH`, `ALLOWED_ORIGIN`, `GOOGLE_CLIENT_ID` вже вказані у `worker/wrangler.toml`. Папку Worker **не потрібно публікувати як вебзастосунок**, вона запускається на Cloudflare.

## Крок 5. Перенесення ваших поточних даних

Це особливо важливо, бо в `data.json` містяться **лише початкові 42 страви без ваших останніх голосувань**.

1. Відкрийте `https://zbys1av.github.io/smakova-liha/`.
2. Імпортуйте свій JSON-бекап із попередньої версії, якщо на новій адресі ще немає вашого прогресу.
3. **Налаштування → GitHub Cloud → Перевірити GitHub**.
4. Якщо ви хочете зберегти в GitHub саме імпортований локальний прогрес, натисніть **«Використати локальну версію»** та підтвердьте вибір.
5. Увійдіть через Google під дозволеним власником.
6. Натисніть **«Зберегти в GitHub»**. У репозиторії з'явиться коміт, який оновить `data.json`.
7. Відкрийте сайт на іншому пристрої. За відсутності локальної бази версія GitHub підвантажиться автоматично.

**Увага:** «Зберегти в GitHub» — ручна дія. Звичайні локальні голосування **не** створюють новий GitHub-коміт автоматично, а лише відображаються як «незбережені зміни». Це зменшує кількість API-запитів і захищає від випадкових комітів.

## Приватність

У цій схемі, як і в оригінальній публічній версії MEDIA / LOG, `data.json` з історією голосувань зберігається в **публічному** репозиторії GitHub. Його **може прочитати будь-хто**. Google OAuth захищає **право запису**, але **не читання**. Якщо результати мають бути приватними, потрібен окремий приватний репозиторій та захищений GET endpoint (не використовуйте цей публічний пакет без модифікацій).

## Перевірки й діагностика

```bash
cd worker
node tests/smoke.mjs
```

Тести не використовують справжнього PAT і не створюють коміти.

| Симптом | Що перевірити |
| --- | --- |
| «Лише читання» | Заповніть `apiUrl` у `cloud-config.js` та перезавантажте сторінку |
| `data.json 404` | Чи є файл у корені гілки, опублікованої GitHub Pages |
| Google Sign-In не видно | HTTPS, правильний Client ID, дозволений OAuth origin, блокувальники скриптів |
| Google `401` | Використовується інший Google-акаунт, токен прострочений чи OAuth client відрізняється |
| GitHub `403`, `502` | Немає Worker Secret `GITHUB_TOKEN`, токен не має Contents write або обмежений іншим repo |
| Конфлікт `409` | Інший пристрій уже записав іншу GitHub-версію; перед повтором звірте копії |
| Локальний прогрес відсутній на новій адресі | Імпортуйте JSON: localStorage прив'язаний до адреси вебсторінки |
| Не працює з `file://` | Локальний режим і JSON працюють, а GitHub Cloud потрібно відкривати через опублікований HTTPS сайт |
